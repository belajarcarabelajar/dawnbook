# Dawnbook AI Assistant Guidelines (GEMINI)

This file contains critical architectural decisions and strict rules for the Dawnbook platform. Any AI assistant working on this repository **MUST** adhere to these rules to prevent regressions and maintain system consistency.

> **Single source of truth (synced):** `AGENTS.md` and `CLAUDE.md` at the repo root are **symlinks to this file** (`GEMINI.md`). Editing any one of the three edits the same underlying content, so all AI tools (Gemini, Claude, OpenCode/agents) read identical guidance. Do NOT "fix" the symlinks by turning them into separate files. Caveat: an editor that saves via atomic rename can replace a symlink with a regular file, breaking the sync, recreate with `ln -s GEMINI.md AGENTS.md && ln -s GEMINI.md CLAUDE.md` if that happens. (Note: `.agents/AGENTS.md` is a separate, older file and is not part of this symlink set.)

## 1. Centralized mdBook Templating
- **Master Template:** The file `books/_template/book.toml` is the absolute source of truth for all mdBook configurations.
- **Auto-Sync:** The `scripts/sync-template.ts` script automatically forces all other `book.toml` files to inherit configurations (like `additional-css`, `additional-js`, and `mathjax-support`) from the master template during the build process.
- **Rule:** **NEVER** manually modify `book.toml` files of individual books. If a global config change is needed, modify `books/_template/book.toml` and the build script will handle the rest.

## 2. Typography and Theme Consistency
- **Custom Fonts:** Dawnbook uses custom fonts (`Syne` for display, `Epilogue` for body) injected via `../../apps/hub/src/styles/typography.css`.
- **NO Strict Tokens:** We **DO NOT** include `tokens.css` inside the mdBook templates. `tokens.css` is strictly for the Hub app and admin dashboard. Injecting it into mdBooks will destroy the native theme capabilities (Light, Rust, Coal, Ayu, Navy) by forcing strict black/white colors.
- **Floating Header:** The `.menu-bar` floating header MUST NOT be transparent. It must seamlessly adopt the native `var(--bg)` background color dictated by the active mdBook theme.

## 3. Caching and Versioning (Disabled)
- **Zero Cache Tolerance:** The platform requires real-time updates. Cloudflare CDN caching is aggressively and permanently disabled via `_headers` using `no-store, no-cache, must-revalidate, proxy-revalidate, max-age=0`.
- **No Cache Busting:** Because caching is disabled at the CDN level, **DO NOT** rename or version shared asset files (e.g., no `shared-header-v2.css`). Use static names (`shared-header.css` and `shared-script.js`) consistently across the project.
- **PWA Service Worker:** Any Service Worker implementation MUST use a "Network-First" (network falling back to cache) strategy. DO NOT use "Cache-First" strategies, as they will permanently cache HTML and assets, breaking the zero-cache tolerance rule.

## 4. Spacing and Aesthetics
- **Header Spacing:** The distance between the floating header and the first title of any chapter is precisely set to `1cm` (`margin-top: 0.8cm` and `padding-top: 0.2cm`). Do not arbitrarily increase or decrease this without explicit user consent.

## 5. Dynamic Progress Tracking Architecture
- **No Hardcoded Books:** The Cloudflare D1 `reading_progress` table and the `/api/progress` endpoint must remain completely agnostic to book slugs. Never hardcode book names or chapter limits in the backend.
- **Client-Side Extraction:** The client-side tracker (`books/shared-script.js`) MUST dynamically parse the mdBook sidebar (`.sidebar-scrollbox .chapter li > a`) to determine the total chapter count and valid paths. Do not attempt to inject hardcoded chapter maps into individual books.
- **Path Normalization (Cloudflare Pages):** Cloudflare Pages automatically strips `.html` extensions from the browser URL. When comparing `window.location.pathname` against tracked `completed_paths`, the logic in both `shared-script.js` and the Hub (`scripts/build.ts`) **MUST** manually append `.html` to the paths before comparison to ensure a strict string match.
- **Hub Synchronization:** The main Hub index must always rely on `manifest.json` (auto-generated by `scripts/build.ts` by parsing `SUMMARY.md` files) to render progress bars accurately.

## 6. Duplication Prevention & File Cleanup
- **No Temporary Files in `src/`:** When importing and processing a new book, raw/temporary markdown files (such as `1.md`, `2.md`, etc., or files with temporary/unformatted names) must be explicitly deleted from the book's `src/` root directory. Only the final, zero-padded kebab-cased chapter files under `src/content/` (e.g., `01_memahami-quarter-life-crisis.md`) should remain on disk.
- **mdBook Wildcard Compilation:** Leaving any untracked or raw markdown files in `src/` causes mdBook to compile them anyway, resulting in duplicate pages in the final build.

## 7. Remote Database Seeding (SQLITE_TOOBIG)
- **Chunked Content Upsert:** Cloudflare D1 query limits restrict individual SQL statement length to 100 KB. Seeding books with large markdown contents (e.g., >100 KB) using a single SQL query will fail with a `statement too long: SQLITE_TOOBIG` error.
- **Sequential Appending:** The database seeder (`scripts/migrate-to-d1.ts`) must insert book metadata with an empty `content_md` first, and then sequentially update the content in chunks of 30 KB using SQLite's string concatenation operator (`content_md = content_md || 'chunk'`) to avoid hitting statement size limits.
- **Command-based Execution:** The `wrangler d1 execute --file` command often fails silently for SQL files containing complex multiline markdown structures and large text data. The seeding script **MUST** execute each statement individually using the `--command` argument (`wrangler d1 execute <DB> --command="..."`) rather than relying on file-based execution.



## 8. Mandatory SEO Meta Descriptions & Google SERP Compliance
- **Mandatory Description Key:** Every book's `book.toml` MUST explicitly define a concise, SEO-optimized `description` field under `[book]` (100–160 characters).
- **Google SERP Standard (110–160 Characters):** Meta descriptions MUST strictly adhere to Google SERP snippet guidelines:
  1. **Root Book Page (`index.html`):** MUST use the authentic, curated `description` from `book.toml`.
  2. **Chapter Pages (`content/*.html`):** MUST extract the lead opening sentence directly without duplicating the page or book title.
  3. **Sentence & Word-Boundary Integrity:** Meta descriptions must NEVER truncate words in half (e.g. `m...`). Priority 1 is a complete, grammatically sound sentence within 160 characters. If a sentence exceeds 160 characters, truncate cleanly at the last complete word boundary before appending `...`.
  4. **Punctuation & Cleanliness:** No stray whitespace before punctuation marks (e.g., no ` .` or ` ,`).
- **Chapter Opener Cap of 155 Characters (measured 2026-10-12):** The chapter-page meta description is the chapter's first sentence passed through `formatSerpDescription(text, maxLen = 155)` in `scripts/inject-gating.ts`, so a first sentence longer than 155 characters is cut at a word boundary and gets `...`. Chapter opening sentences MUST therefore be at most 155 characters (two 158-character openers were truncated in the 2026-10-12 measurement).
- **Rule:** Never create, scaffold, or compile a book without verifying that all pages satisfy these Google SERP meta description standards.

## 9. Mandatory AI Brain Model Line-by-Line File Inspection (No Script-Only Formalities for LaTeX)
- **STRICT MANDATE — AI BRAIN MODEL INSPECTION ONLY:** Every LaTeX audit and verification MUST be performed using the AI Agent's cognitive brain model through direct, line-by-line file reading (`view_file`) and manual inspection. Relying ONLY on automated scripts (like `check-latex-support.ts`) as a formality or lazy shortcut is STRICTLY FORBIDDEN. Automated check scripts are ONLY post-flight verification safety nets, NEVER a replacement for manual AI reading.
- **Mandatory Two-Phase LaTeX Workflow:** For any task involving LaTeX rendering or verification:
  1. **Phase 1 (Detection & Counting via AI Brain):** You MUST call `view_file` to read the file, detect all LaTeX formulas on the page/file using AI reasoning, and count the total number of LaTeX instances.
  2. **Phase 2 (Agentic Editing & Verification):** Once all instances and total counts are identified and verified, proceed with line-by-line edits directly using agentic coding tools (`view_file` and `replace_file_content`).
- **FORBIDDEN AUTOMATION SCRIPTS FOR LATEX:** Automation scripts, Node batch converters, mass regular expression search-and-replace scripts, or automated transformation tools for any LaTeX task are STRICTLY FORBIDDEN. All LaTeX tasks must be handled manually line-by-line by the agent using AI reasoning.
- **Pulldown-cmark `<em>` Tag Prevention:** Ensure all underscores (`_`) inside math delimiters are handled cleanly so that `pulldown-cmark` never injects `<em>...</em>` emphasis HTML tags inside MathJax/KaTeX expressions.
- **`<div>` Wrapping Does NOT Stop Escape Processing (measured 2026-10-12, mdBook v0.5.4):** The HTML block opened by `<div>` ends at the first blank line, so the `$$` lines are parsed as a normal Markdown paragraph, where a backslash before ASCII punctuation is removed: `\,` renders as a comma, `\\` becomes a single backslash (so `\begin{cases}` rows collapse), and `\{` becomes `{`. `\text{\%}` still works only because it becomes `\text{%}`, which MathJax shows as a literal percent.
  - **Rule:** Never write `\,` `\;` `\!` `\\` `\{` `\}` `\|` inside math, not even in a protected block (below), so a formula stays correct if a blank line is ever added inside its block; use `\quad`, `\times`, or separate equations instead of `cases`. Existing books may contain these macros and need a manual line-by-line audit (no batch LaTeX scripts, per the rule above).
- **Protected display block (measured 2026-10-21, mdBook v0.5.4 and MathJax 2.7.9 in Chromium):** with NO blank line between `<div>` and `</div>` (`<div>`, `$$`, formula, `$$`, `</div>`, with a blank line before and after the whole block), the block is raw HTML and reaches MathJax exactly as written. Write every display formula this way; inside a list item, indent all five lines to the item's text column. Because nothing is stripped there, MathJax prints some escapes literally:
  - percent is `\%` in math mode (`100\%`); `\text{\%}` shows a literal "\%" in this block;
  - `\&`, `\_` and `\%` inside `\text{...}` show their backslash; write `\text{A } \& \text{ B}` and words with spaces instead of underscores;
  - `\lbrace` `\rbrace` `\Vert` `\$` work;
  - MathJax 2 does not wrap display math, and the reading column is 750 px wide on desktop: a longer formula (often a chain of `\text{...} \rightarrow` steps) does not fit and the reader has to scroll it sideways (section 10). Split it into two protected blocks, the second starting with `\quad +` or with the arrow;
  - the `\text{\%}` rule in item 5 below applies only to math in ordinary Markdown (inline `$...$` in paragraphs, list items and table cells, or an old `$$` block that is not protected), where mdBook removes the backslash before MathJax runs.
- **Underscores in inline math (measured 2026-10-21):** two subscripts in one paragraph can pair into `<em>` tags (for example `$\text{A}_{i} + \text{B}_{j}$`), which MathJax cannot typeset. Write the underscore as `\_` in inline math whenever a paragraph holds more than one subscript; mdBook turns `\_` into `_`. Never use `\(`...`\)` or `\[`...`\]` delimiters in Markdown: mdBook strips their backslashes.
- **Currency:** never leave a bare `$` amount in prose when another `$` can follow in the same paragraph; write "USD 700 juta" or "1,78 juta dolar AS". Quoted titles keep their wording.
- **LaTeX & Formula Verification Checklist — MANDATORY, ZERO-EXCEPTION:**
  1. **Inline Math Delimiters:** Use `$ ... $` in `.md` files (not `\( ... \)`, see "Underscores in inline math" above). Standard `$math$` (with NO spaces inside `$`, e.g., `$P_e$`) is recommended so GitHub renders equations natively in repository view; MathJax, configured in `books/_template/theme/head.hbs`, renders `$ ... $` in the browser, and the build does not rewrite it.
  2. **Display Math Delimiters:** Use `$$ ... $$` in `.md` files, always in the protected block described above.
     - **Standalone Display Math:** `$$` on its own line inside `<div>`, with a blank line before and after the whole block and none inside it.
       ```markdown
       <div>
       $$
       \text{MC} = \frac{d\text{TC}}{dQ} = 10Q + 20
       $$
       </div>
       ```
     - **Display Math Inside List Items:** Indent the whole block by 3 spaces (the item's text column) to keep the ordered list hierarchy without triggering CommonMark 4-space code-block traps:
       ```markdown
       1. Cari $\text{MC}$ (*Marginal Cost*) dari turunan $\text{TC}$:

          <div>
          $$
          \text{MC} = \frac{d\text{TC}}{dQ} = 10Q + 20
          $$
          </div>
       ```
  3. **MANDATORY BLANK LINES AROUND DISPLAY MATH:** Every standalone `$$` block MUST be preceded by a blank line AND followed by a blank line. If a display math block is written without blank lines separating it from surrounding text, pulldown-cmark renders it inside a `<p>` tag, causing the formula to appear **inline and scrambled**.
  4. **Multi-Letter Variables:** All multi-letter variable names (e.g. `TR`, `AR`, `MR`, `PED`, `PES`, `ATC`, `MC`, `DWL`, `HHI`, `WTP`, `FC`, `TC`, `AC`, `Es`, `Ed`) MUST be wrapped in `\text{...}` (e.g. `\text{PED}`).
  5. **Percentage Signs `%` in Math (CRITICAL):** The `%` character is a TeX comment delimiter. Inside ANY math block (`$ ... $` or `$$ ... $$`), a raw `%` or `\%` will cause MathJax/KaTeX to silently discard everything from that point to end-of-line, making the entire formula invisible. **MANDATORY RULE:** Every percentage sign in ordinary Markdown math (inline `$ ... $`, or a `$$` block that is not protected) MUST be written as `\text{\%}`. Inside a protected display block, write `\%` instead (see "Protected display block" above). Examples:
     - ✅ CORRECT: `$ 50 \text{\%} $` (inline)
     - ✅ CORRECT: `E_d = \frac{\% \Delta Q}{\% \Delta P}` as the formula line of a protected block
     - ❌ WRONG: `$ 50\% $` (escaped `\%` — mdBook strips backslash, becomes raw `%`)
     - ❌ WRONG: `\text{\%}` inside a protected block (prints a literal "\%")
  6. **Formula Context:** Verify every formula matches the surrounding paragraph context and economic/mathematical meaning.
- **LaTeX Auditing via Generative AI Brain Model Only:** Automated check scripts (such as `check-latex-support.ts`) are REMOVED from build blocking gates. All LaTeX formula inspection, verification, and formatting MUST be performed 100% by the Generative AI model reading files line-by-line (`view_file`) using AI reasoning.
- **Double-Nesting Forbidden:** Batch find-replace scripts that target `\text{\%}` WILL produce `\text{\text{\%}}` if the pattern already exists. NEVER run a second pass of `\%` → `\text{\%}` replacement. In ordinary Markdown math the correct form is `\text{\%}`, single nesting only; in a protected block it is `\%`.

## 10. MathJax Loading & Navigation Rendering (Learned from Production Bug)
- **`defer` Not `async` — MANDATORY:** The MathJax `<script>` in `books/_template/theme/head.hbs` MUST use `defer`, NEVER `async`. With `async`, the browser executes MathJax immediately when its file is served from cache (nearly 0ms). If this happens before the HTML body is fully parsed, MathJax scans an incomplete DOM and misses all formulas that appear later. With `defer`, MathJax is guaranteed to run ONLY after the full HTML is parsed.
  - ✅ CORRECT: `<script data-cfasync="false" defer src="...MathJax.js..."></script>`
  - ❌ WRONG: `<script data-cfasync="false" async src="...MathJax.js..."></script>`
- **sync-template.ts propagates head.hbs:** After editing `books/_template/theme/head.hbs`, ALWAYS run `bun run scripts/sync-template.ts` to propagate the change to all 37+ books. Never manually edit individual books' `head.hbs`.
- **`pageshow` + bfcache Safety Net — MANDATORY in `shared-script.js`:** `books/shared-script.js` MUST contain a `pageshow` event listener with `e.persisted` check to call `MathJax.Hub.Queue(['Typeset', MathJax.Hub])`. This fixes iOS Safari swipe-gesture navigation (back-forward cache) where scripts do NOT re-execute and MathJax never re-renders the restored DOM.
  ```javascript
  window.addEventListener('pageshow', function(e) {
      if (e.persisted && window.MathJax && window.MathJax.Hub) {
          window.MathJax.Hub.Queue(['Typeset', window.MathJax.Hub]);
      }
  });
  ```
- **`window.load` Re-typeset Safety Net:** `shared-script.js` MUST also call `MathJax.Hub.Queue(['Typeset', MathJax.Hub])` on the `window.load` event as a final safety net for any edge cases.
- **Symptom Check:** If a user reports "LaTeX works on Module 1 but breaks on Module 2, manual refresh fixes it" → root cause is either `async` (race condition) or bfcache. Check `head.hbs` for `async` first.
- **Wide display math scrolls on its own (measured 2026-10-21):** `books/shared-header.css` sets `.content .MathJax_Display { overflow-x: auto; overflow-y: hidden; padding: 3px 0; }`. Before that rule, at a 390 px phone viewport (350 px column), formulas wider than the column made the whole `.content` column scroll sideways on 193 chapters in 46 books, and the rest of the formula was cut off at the screen edge. Do not remove the rule or move `overflow` onto `.content`.
  - The padding is required: without it `overflow-y: hidden` cut the bottom pixel row of the descenders in `\text{... hingga ... bintang}` (multiple-intelligences 10). Keep it in whole pixels: 0.15em changed the rendering of 6 of 15 formulas in a screenshot test. The padding adds 3 px of space above and below every display formula.
  - Verification: a before/after screenshot of all 583 display formulas at 1280 px (each crop follows the formula, with a clip-path control that must show differences) showed 0 changed with `3px`.
  - After the rule, at 390 px, 206 display formulas scroll inside their own box. This rule does not cover inline `$...$` math: a long inline formula still widens its paragraph and shifts the whole column (33 chapters at 390 px and 39 at 360 px before they were converted on 2026-10-21; 0 after). Keep inline math well under 275 px rendered (the narrowest one that overflowed, inside a list item at 360 px); write anything longer as a protected display block, or for a "symbol = words" definition put only the symbol in math (`$D$ = durasi interupsi`).
  - Some display boxes report 2 to 5 px of hidden vertical overflow (`scrollHeight` above `clientHeight`). The amount is the same at 390 and 1280 px, and at 1280 px the screenshot test shows no visible change, so no visible ink is lost there.

- **`<div>` Wrapped Display Math:** All display math equations MUST be wrapped in `<div>\n$$ ... $$\n</div>` with blank lines before and after to prevent `pulldown-cmark` from parsing internal underscores into HTML `<em>` emphasis tags.

## 21. Anti-Template: Varied, Human-Sounding Structure (No Repeated Scaffolding)
- **The problem this prevents (observed 2026-09-28):** all 11 content chapters of a book ended with the identical heading `## Rangkuman`. Same words, same position, 11 times. Readers notice the template, not the content.
- **Rule: no structural element may repeat verbatim across chapters of one book.** This covers closing section titles, opening hooks, transition sentences into the next module, and any other recurring scaffold. Same function is fine, same wording is not.
- **Closing sections:** each chapter's recap keeps its summarizing function but MUST carry a different title. The orchestrator assigns one distinct closing title per chapter in the dispatch prompt itself (examples: `Ringkasan`, `Inti Pembahasan`, `Poin Penting`, `Benang Merah`, `Recap`, `Yang Perlu Kamu Ingat`, `Intisari`, `Poin Kunci`, `Kesimpulan Bab`, `Key Takeaways`, `Penutup` for the final chapter). Never leave the choice to each subagent independently, independent agents converge on the same default word.
- **Same principle for openers and transitions:** vary the first-paragraph device (scenario, question, paradox, data point) and the bridge sentence to the next module. If two chapters open with the same rhetorical move, rewrite one.
- **Invented example characters and scenes (measured 2026-11-05):** when chapters may invent a hypothetical person or scene, the orchestrator assigns each chapter its own character name and situation in the dispatch table, and no two chapters of a book share either. "Use a new name" alone is not enough: in the book "Simbolisme Alam dalam Sastra", 7 of 13 parallel writers chose the same name and 3 gave that character the same job-loss scene. Verification: list the invented names per chapter in the parent audit and fail it on any repeat.
- **Verification (mandatory, before pre-flight):** extract all `## ` headings per chapter and fail the review if any non-topical heading (closers, recurring scaffolds) is identical across two or more chapters, e.g. `grep -h '^## ' books/<slug>/src/content/*.md | sort | uniq -d` must return nothing except genuinely shared headings.
- **Priority note:** variety never overrides correctness. A varied heading that misdescribes its section is worse than a repeated one; pick a different accurate title, not a random synonym.

## 24. Heading Anti-Colon Rule (No "Judul: Subjudul" Headings)
- **Forbidden pattern (observed 2026-10-11):** a colon (`:`) in any heading of a chapter file (`##` to `######`, including a heading inside a blockquote or list item), in any `SUMMARY.md` entry title, or in the `title` value of `book.toml` for a NEW book. This covers `Label: Subjudul`, a numbered `4. Label: Subjudul`, and a trailing colon such as `Komponen SMART:`. A scan on 2026-10-11 found 2,516 such headings across 56 books (613 of 712 chapter files). The two-part title is a recognizable AI tell, and readers see the template instead of the content.
- **Do not disguise the pattern.** Never swap the colon for a dash, semicolon, parentheses, or a hollow "dan". That is the same two-part title in a different costume. Rewrite the heading into one natural phrase, picking one of four ways:
  1. **Keep the specific part.** If the subtitle carries the real meaning, use it and drop the generic label (`Analogi: Antrean di Kasir` becomes `Antrean di Kasir`).
  2. **Keep the label.** If the subtitle only restates the label, use the label alone.
  3. **Fuse both.** If both parts matter, merge them into one noun phrase, verb phrase, or question.
  4. **Trailing colon.** Drop the colon, and turn a list lead-in into a noun phrase (`Komponen SMART:` becomes `Komponen SMART`, or a fuller noun phrase when the heading introduces a list).
- **Scaffold-label cap (extends section 21):** a generic label such as `Analogi`, `Real-World Application`, `Aplikasi Dunia Nyata`, `Studi Kasus`, `Skenario`, `Kasus`, or `Kesimpulan` may be the first word of at most 2 headings per book. If a section is plainly an analogy or a case, the label can be dropped entirely. Keep the number prefix, heading level, language, and meaning of the original heading, and add no new claims.
- **Chapter titles keep the topic (observed 2026-10-11):** the first heading of a chapter file and its `SUMMARY.md` entry (kept identical to each other, and the source of the page `<title>`) MUST keep the topic named by the old label. Keep the label half and drop the subtitle (`Teori Permainan Evolusioner: Saat Biologi Bertemu Strategi` becomes `Teori Permainan Evolusioner`), or fuse both halves into one natural noun phrase (`Menjinakkan Gangguan Komunikasi dan Notifikasi`). A bare colon-to-space swap that leaves a subject+verb clause (`Planning Menentukan Arah ...`) or a mid-title ordinal (`Fase 1 Bulan Madu`) is the same slop; keep one half or use one varied connector. A bare tagline (`Seni Berbagi Secara Adil`) hides the topic and is a defect. A generic label alone (`Pendahuluan`, `Pengantar`, `Kritik`) may be dropped when the subtitle names the topic.
- **Connector cap (observed 2026-10-11):** `Subjudul sebagai Label` repeated across a book is the same template as `Label: Subjudul`. One connector word (sebagai, dengan, lewat, melalui, untuk, dalam, pada, saat, menurut) may appear in at most max(4, 15%) of the headings rewritten in one book, and at most half of the rewritten headings may be longer than the heading they replace. Prefer dropping the redundant half over fusing both. Sequence labels (`Langkah N`, `Kasus N`) become a plain `N. Judul` or are dropped; never glue an ordinal to the end (`... sebagai Langkah Kedua`).
- **Exemption marker:** the verbatim title of a cited work that contains a colon (for example a book title) may stay if the heading line ends with `<!-- heading-colon-ok: <reason> -->`. The reason is mandatory, and every use must be listed in the report. Do not use the marker to avoid a rewrite. A colon inside a code span or math is not counted.
- **Owner-approved one-time exception to section 1 (2026-10-11):** the owner allowed editing ONLY the `title` line of `books/metakognisi/book.toml`, `books/pembelajaran-multidisiplin/book.toml`, and `books/quarter-life-crisis/book.toml` to remove the colon. Every other `book.toml` edit stays forbidden, including any other key in those three files.
- **Dispatch requirement:** every authoring or subagent dispatch prompt that writes or edits chapter headings, `SUMMARY.md`, or a `book.toml` title MUST carry this rule in the prompt text itself. Do not assume the subagent has read this file.
- **Bold sub-titles (2026-10-11):** a paragraph that is only bold text (up to 100 characters) works as a sub-title and follows the same colon rule (`**Analogi: Mesin ATM**` becomes `**Analogi Mesin ATM**`). Inline lead-ins (`**Penting:** teks sesudahnya`), trailing-colon labels (`**Contoh Soal:**`), and long callouts are body text and stay. Owner decision 2026-10-16: bold text with a colon inside it followed by body text on the same line (`**Analogi: Klub Eksklusif** Bayangkan ...`, also after `>`) is the same pattern and is flagged, while a colon at the end of the bold (`**Penting:** teks`) stays an inline lead-in. The detector flags the sub-title form, and `--diff-guard` lets such a line change the way it lets a heading change.
- **Forms that are NOT the pattern (decided 2026-10-11):** ` vs. ` comparisons, numeric ranges (`(7 - 11 Tahun)`), acronym expansions (`P - Planning`), and parenthetical glosses (`(Center of Pressure - CP)`) are legitimate and must not be rewritten. A dash used as `Label - Subjudul` is the pattern in a different costume; it is not detected mechanically, so reviewers catch it.
- **Repeated headings (2026-10-11):** the same heading text in 3 or more chapters of one book fails (`colab-test -C <checkout> -- bun run scripts/check-repeated-headings.ts`, also run by the build gate). Name each heading from its own section and give each chapter closer a different title (section 21). The mechanical gate starts at 3 chapters so a coincidental pair does not break the build; section 21 still applies in review, so two identical non-topical closers remain a defect to fix at authoring time. Bold sub-titles may hold italic emphasis (`**Skenario: *Burnout* di Kantor**` is flagged too).
- **Structure gate (added 2026-10-24):** `bun run build` runs `scripts/check-book-structure.ts` over every book (slugs starting with `_` are skipped) before the mdBook builds and exits 1 on any problem: the chapter title must be a level-2 heading equal to its SUMMARY title, no section heading may repeat in two chapters of a book (this gate fails at 2, stricter than the 3 of `check-repeated-headings`, matching section 21), every opener's first sentence must survive the 155-character meta cut (section 8), plus the checker's other rules (SUMMARY and disk agree, no stray markdown in `src/`, `book.toml` description of 100 to 160 characters, no em dash, emoji or "Anda", link targets that resolve), and a book with no chapters fails. Run it alone with `colab-test -C <checkout> -- bun run check:structure`, or for one book with `colab-test -C <checkout> -- bun run scripts/check-book-structure.ts <slug>`. Revert: remove the `runStructureGate` call in `scripts/build.ts` and the `check:structure` script in `package.json`.
- **Verification (mandatory):** `colab-test -C <checkout> -- bun run scripts/check-heading-colons.ts` (read-only detector, exit 1 on any violation, exit 0 when clean). It also lists every `heading-colon-ok` marker so exemptions stay visible. ## 25. Mermaid Diagrams (Build-Time SVG)
- **What it is:** a fenced `mermaid` code block in a chapter is rendered on the author's machine into an inline SVG. The page loads no diagram JavaScript.
- **Cache location:** each rendered SVG lives in `books/<slug>/diagrams/<hash>.svg`, one file per distinct diagram, committed with the chapter. The folder sits outside `src/`, so mdBook never publishes it as a file; the diagram reaches the reader only inline in the chapter HTML and stays behind the paywall. Never copy or link a cached SVG into `src/` (`.svg` is a public asset extension in the gating middleware).
- **CI never renders:** the build replaces each block with its cached SVG in the `.build-tmp` copy and exits 1 on a cache miss, naming the book, file, line and `bun run diagrams:render`. CI has no browser by design.
- **When a diagram helps:** only where the chapter text already carries one of these shapes:
  - a multi-step process, a cycle, or a decision with branches;
  - a chronology whose dates are in the text;
  - numbers already stated in the text (`pie`, `xychart`);
  - a two-axis classification the text describes (`quadrantChart`);
  - an ASCII-art diagram inside a code fence. Convert it and delete the ASCII version, so a book never carries two drawing styles.
- **Never required:** most chapters have no diagram, and a chapter with no fitting candidate stays without one. At most 3 per chapter (gate rule `too-many`), and the same diagram twice in one chapter is refused (`duplicate`). Do not repeat the same diagram shape across chapters as scaffolding (section 21).
- **Grounding (hard rule):** every node, edge, label and number must be stated in the same chapter. Add no new fact, no new number, and no causal arrow the text does not state. One source per chart: never merge figures from two sources into one chart. If two chapters disagree, fix the text first; a diagram never picks a side.
- **Placement:** put the block after the paragraph it illustrates and introduce it with a prose sentence. Never make it the first block of a chapter (`first-block`), because the chapter meta description comes from the first paragraph (section 8). To drop a diagram, delete the block; never wrap it in `<!-- -->`, because the first `-->` arrow inside ends the HTML comment early and the rest of the block leaks into the page.
- **Width:** keep the natural width (the third number of the cached SVG's root `viewBox`) at or under 1000 px (gate rule `too-wide`), because the SVG never shrinks below 0.75 of it and the reading column is 750 px. Write chains longer than four nodes as `flowchart TD`, keep sequence diagrams to the participants the text needs, and never use `<br/>` inside a label (sequence diagrams wrap their own text). Flowchart labels wrap at 110 px, and a single word wider than that is split across two lines (gate rule `split-word`); reword the label, for example with a shorter synonym or by dropping a suffix, never with `<br/>`.
- **Allowed types:** `flowchart` (or `graph`), `sequenceDiagram`, `stateDiagram-v2`, `pie`, `quadrantChart`, `xychart` (`xychart-beta` accepted) and `timeline`. `mindmap` and every other type are refused (`type-not-allowed`); write a mindmap candidate as a flowchart.
- **Accessibility:** every block declares `accTitle:` and `accDescr:` in Indonesian (`missing-acc-title`, `missing-acc-descr`). The renderer injects them into `timeline`, which Mermaid otherwise drops silently.
- **Flowchart labels:** quote any node label that contains brackets or punctuation (`A["Biaya (Rp)"]`) and quote every edge label (`A -->|"ya"| B`).
- **xychart strings and numbers:** quote every title, axis title and category (`xychart-unquoted`). Numbers use a dot decimal and no thousands separator: `2170.2`, never `2.170,2`, which renders wrong values with no error (`xychart-decimal`). A number with a dot and exactly three digits after it (`1.500`) is refused as a thousands separator (`xychart-thousands`). Each series has one value per category (`xychart-count`).
- **Forbidden inside a block:** `{{` (mdBook processes it even inside the SVG, `double-brace`), a straight double quote inside a label (use curly quotes “ ”; the gate enforces this as `straight-quote` in quoted flowchart labels and in the text after `:` in sequence and timeline lines), a Mermaid directive `%%{...}%%` or a front-matter `config:` key, which would override the locked render config (`config-override`), emoji (`emoji`), em dash (`em-dash`), the word "Anda" (`anda`), and `$` (`dollar`).
- **Example** (assuming the chapter describes these four steps as a repeating cycle):
  ````markdown
  ```mermaid
  flowchart LR
      accTitle: Siklus PDCA
      accDescr: Empat tahap PDCA berjalan berurutan dari rencanakan, kerjakan, periksa, sampai tindak lanjuti, lalu kembali ke rencanakan.
      A["Rencanakan (Plan)"] --> B["Kerjakan (Do)"]
      B --> C["Periksa (Check)"]
      C --> D["Tindak lanjuti (Act)"]
      D -->|"siklus berikutnya"| A
  ```
  ````
- **Workflow:**
  1. Write the block in the chapter.
  2. Run `HEAVY_LOCAL=writes-svg-cache bun run diagrams:render` on this PC, because it writes the SVGs you commit. It renders only new or changed diagrams with the local Chromium (`PUPPETEER_EXECUTABLE_PATH`, else `/usr/bin/chromium`) and reports rendered, cached and orphaned entries. `--book <slug>` limits it to one book; `--prune` deletes orphans.
  3. Run `colab-test -C <checkout> -- bun run check:diagrams`. It exits 1 on any violation and lists book, file, line and rule id; orphans are warnings. The same gate runs inside `bun run build`.
  4. Commit the chapter together with `books/<slug>/diagrams/`.
- **Locked render config:** `scripts/diagrams/render-config.json` and `scripts/diagrams/theme.css` are part of every cache key, together with the diagram source, the pinned `@mermaid-js/mermaid-cli` version, the installed `mermaid` version (read from `bun.lock`) and the source of `scripts/diagrams/postprocess.ts`. Changing either file, upgrading Mermaid, or changing the post-processor renames every cached SVG, so the same change needs a full `bun run diagrams:render` followed by `--prune`. Never edit them for one book's sake.
- **One SVG for all themes:** text, lines, shapes and backgrounds take their colours from mdBook CSS variables (`--fg`, `--bg`, `--quote-bg`, `--links`), so one SVG follows light, rust, coal, navy and ayu. The first xychart series follows `--links`; pie slices and further xychart series use a fixed 8-colour palette chosen to keep at least 3:1 contrast in all five themes, so avoid a pie with more than 8 slices.
- **Dispatch requirement:** every authoring or editing dispatch prompt that may add or change a diagram MUST carry this rule in the prompt text itself. Do not assume the subagent has read this file. Paste this contract paragraph:
  ```text

Add one (at most 3 per chapter) only where this chapter already states a multi-step process, a cycle, a decision, a dated chronology, numbers, or a two-axis classification, and convert any ASCII-art diagram in a code fence into one.
  Grounding: every node, edge, label and number must be stated in this chapter. Keep the text's hedges and examples (sering kali, dapat, misalnya), never turning a hedged claim into a rule or an example into the cause.
  Placement: after the paragraph it illustrates, introduced by a prose sentence, never the first block of the chapter. The introducing sentence must differ in wording from the other diagram intros of the same book.

## 29. Cooked Prose, Not Raw Sources (Owner Rule, 2026-10-24)
- **Why this exists:** the book "Pelajaran Hidup dari Harvest Moon Back to Nature" (PR #184) went live with every fact correct and every gate green, and the owner found it stiff, AI-like and not pleasant to read ("gak enak dibaca", "tulisan yang tidak memiliki jiwa"). The sources were served raw, like sashimi, instead of cooked. A reader who meets hollow prose leaves, and a book without a voice damages the whole platform. The owner calls this failure fatal; correctness alone is not done.
- **Measured symptoms (13 chapters):** "Panduan ..." as the subject of a sentence 50 times, "tokoh kita" 51, "Menurut panduan" 27, "panduan resmi Prima" 24, "mirip dengan" 16, "Kalau dipikir-pikir" 14, and the same shape in every chapter (scene, source facts, one study with stacked caveats, 4 to 5 recap bullets).
- **Rule:** every chapter is the author's own essay. The author has read the sources, digested them, and now tells the reader what matters, in their own words.
  1. **Choose, then cook.** Take the two to four details that carry the chapter's point and leave the rest in the notes. Dropping a fact is fine; dumping every price, date, list item or sample size is not.
  2. **Name a source once.** A book, guide or study is named where it first matters (author and year or title, one link), then its content is told as plain statements. Never open sentence after sentence with "Panduan menyebut", "Menurut panduan", "Studi itu mencatat", "tulis X".
  3. **Turn research into insight.** One or two sentences that say what was found and why it matters to the reader, with one compact hedge ("dalam percobaan itu", "pada pesertanya", "baru sebatas keterkaitan"). Do not stack disclaimers, and do not drop the hedge either: a correlation stays a correlation, an estimate stays an estimate.
  4. **No raw quotes.** Paraphrase in Indonesian. A short quote only when its wording is the point, never as a stand-in for explaining.
  5. **Kill stock scaffolds.** Banned connectors: "Kalau dipikir-pikir", "Perhatikan", "Di situlah letak", "Ada satu detail/catatan kecil", "Menariknya", and any phrase repeated as a crutch across chapters. Vary how chapters open, how paragraphs are built, and how recaps look (section 21): a recap can be three tight bullets or a short paragraph.
  6. **Rewriting never adds.** When an existing chapter is rewritten for voice, facts may be dropped but never added: no new fact, number, name, cause, mechanic, generalisation or superlative, and no hedge made stronger. Measured 2026-10-24: the first voice rewrite of the Harvest Moon book slipped in 14 such additions ("hadiah termahal di desa", "di musim apa pun", "kapan saja") that two reviewers had to catch.
  7. **Vary the seams.** Do not end every chapter with the same bridge ("Bab berikutnya membahas ..." closed 12 of 13 chapters in that book); use a question, an image, or no bridge. Watch crutch words ("tetap", "pun", "bahkan", "justru") that pile up when prose is compressed.
  8. **Write for one reader.** Address the reader as "kamu" (section 16), use concrete scenes and verbs, and let sentences differ in length. If a paragraph could be pasted into any other book unchanged, rewrite it.
  9. **No contrast framing, no reveal colons (owner, 2026-11-02).** The owner called "Itu temuan pada studi yang mereka tinjau, bukan jaminan untuk semua orang, tetapi pesannya jelas: ..." sloppy AI writing and asked for the same fix everywhere. Do not build sentences on "bukan X, tetapi Y", the trailing "X, bukan Y", the two-sentence "A bukan X. A-nya adalah Y.", or "bukan hanya X, tetapi juga Y"; say what is true, and keep a plain negation only when it carries information ("belum diuji pada mahasiswa"). Inside a paragraph, do not use a colon to reveal, explain or list ("Alasannya sederhana: ..."); split the sentence or join it with a fitting word. Colons stay in cited titles, links, code, times and ratios, definition-list labels, and a lead-in that ends a paragraph right before its list, table or formula. Measured in the three revised premium books before their sweep: 330 occurrences of "bukan" (232 of them ", bukan") and about 600 colons inside paragraphs and list items.
  10. **Evidence lives in the prose, never in a label (owner, 2026-11-02).** The owner rejected the line `**Kekuatan bukti:** terbatas, ... Rujukan: [..](..)` that closed every hack of the three revised premium books, and its striped callout box, as a template that does not blend with the book. Tell a study where the claim is made: name it once with the link on the author and year or the title, say what it found in one or two sentences, and keep the one hedge that carries its strength ("pada 87 mahasiswa", "baru sebatas keterkaitan", "belum diuji lewat penelitian"). Vary where it lands (inside the paragraph that makes the claim, as the reason before a step, as a limit after it, inside a list item) so no new shape repeats from hack to hack, and never write "buktinya kuat/sedang/terbatas" as a stand-in for the label. No bold lead-in such as `**Kekuatan bukti:**` and no `Rujukan: [...]` tag.
- **Self-check before returning a chapter:** read it aloud in your head. If it sounds like a report, a summary of sources, or a template, it is not done. Count the source-attribution openers and the stock connectors; more than two of either in a chapter is a rewrite, not a trim.
- **Mechanical guard:** a book test should cap the measured scaffolds per chapter. Example: `tests/books/pelajaran-hidup-dari-harvest-moon-back-to-nature.test.ts` caps 0 "Kalau dipikir-pikir", 0 "Menurut panduan", 0 stock connectors, 0 "bab berikutnya", at most 2 "tokoh kita" and at most 2 mentions of the word "panduan" per chapter. A green guard is necessary, not sufficient: the parent audit and the reviewers judge the voice too.
- **Build gate (added 2026-10-24):** `scripts/check-voice.ts` holds the shared caps (0 "Kalau dipikir-pikir", "Menurut panduan", "tulis panduan", stock connectors "Perhatikan(lah)", "Di situlah letak(nya)", "Menariknya", "Ada satu detail/catatan", and "bab berikutnya"; at most 1 "mirip dengan" and 2 "tokoh kita" per chapter). `bun run build` runs it over every book before the mdBook builds and exits 1 on any hit (`colab-test -C <checkout> -- bun run check:voice` runs the same check alone). A line that quotes a source verbatim, such as a classroom transcript, may keep a flagged word when it ends with `<!-- voice-ok: <reason> -->`; the reason is mandatory and the marker is for verbatim quotes only, never for the author's own prose. The 2026-10-24 scaffold pass (plan 2026-10-24-dawnbook-voice-scaffold-48-books) brought all 60 books to 0. Since 2026-11-02 it also enforces item 9 in every checked book (the free books after their four-wave sweep, plan 2026-11-02-free-books-contrast-sweep, and the premium books with `"edition": 2026`), at 0 per chapter for "bukan ... tetapi/tapi/melainkan/namun" within one sentence and for the trailing ", bukan", headings included; it does not count blockquote lines, fenced code blocks (Mermaid diagrams), or the tag question ", bukan?". Reveal colons are not checked mechanically; reviewers catch them. Since 2026-11-02 it also enforces item 10 in every checked book, at 0 per chapter for "Kekuatan bukti:" (any bold form) and for a "Rujukan:" tag right before a link.
- **Dispatch requirement:** every authoring or rewriting dispatch MUST carry this contract paragraph in the prompt text itself:
  ```text

Choose the two to four details that carry the point and tell them in your own words; leave the rest out. When rewriting an existing chapter, you may drop facts but never add a fact, number, name, cause, mechanic, generalisation or superlative, never strengthen a hedge, and keep the links of the studies you still mention. - **Sign-in through belajarcarabelajar.com (added 2026-11-01):** buyers whose purchase email is not a Google account sign in through the store. The sign-in page and the premium 403 page offer "Masuk lewat akun belajarcarabelajar.com", a link to Dawnbook `/api/auth/bcb/start?next=<path>`, which sends the reader on to `https://belajarcarabelajar.com/masuk-dawnbook?next=<path>&s=<state>`. That route lives in the bcb repository and requires the store session (email code or Google); it answers 303 to `/api/auth/bcb?t=<token>&next=<path>&s=<state>` on Dawnbook, which sets the session cookie and redirects to the safe `next`. Against login CSRF the links go through the same-origin `/api/auth/bcb/start?next=<path>`, which stores 32 random bytes (43 base64url characters) in the `__Host-bcb_sso_state` cookie (`Path=/`, no Domain, 10 minutes, HttpOnly, Secure, SameSite=Lax; the `__Host-` prefix stops a sibling subdomain from planting it, and a cookie under the old unprefixed name is ignored) and passes the same value to the store as `s`, which the store must return as `s` on `/api/auth/bcb`; the hand-off answers `sso_invalid` unless cookie and `s` match, checked before the token is read or its nonce used, and clears the cookie on every response, so a link carrying someone else's token cannot sign a visitor in to that account.
  - **Token:** `base64url(email).exp.nonce.signature`, where the signature is HMAC-SHA256 over `dawnbook-sso|<email>|<exp>|<nonce>` with the shared secret (`functions/lib/bcb-sso.ts`). `exp` is at most 120 seconds ahead, and each token is single use: its nonce is recorded in `rate_limits` as `sso:<nonce>`.
  - **Users:** a new user created by the hand-off gets `google_sub = "bcb:<email>"`. The Google callback (`functions/api/auth/callback.ts`) links such a user on the first Google sign-in with the same email, and refuses an email already owned by another Google account with `account_conflict`.
  - **Secrets (entered by the owner, never by an agent):** `BCB_SSO_SECRET` on the Dawnbook Pages project and `DAWNBOOK_SSO_RAHASIA` in the bcb Worker env `apex`, the same value, at least 32 characters.
  - **Failure modes:** `/sign-in?error=sso_unavailable` when the secret is missing, `/sign-in?error=sso_invalid` for an expired, forged, malformed or reused token. Both fail closed.
  - **Cross-repo contract:** both repositories check the shared fixture `tests/fixtures/sso/token.json`, so a change to the token format must land in both at once.
  - **Revert:** delete the secret on either side (both sides then fail closed), or revert the pull requests.
- **Premium images in R2 (added 2026-11-01):** the images of a premium book are not in the Pages output. They live in the R2 bucket `dawnbook-premium-media` (binding `PREMIUM_MEDIA`) under `books/<slug>/images/<path>`, and the middleware serves `/books/<slug>/images/...` from the bucket after the same access check as the pages. Images under `images/public/` (chapter 1) need no session, and a missing binding answers 503. A free book's images stay on Pages.

## 31. Indexing Hygiene (Measured 2026-11-07)
- **Why:** the Search Console page indexing export of 2026-11-07 showed 537 indexed and 759 not indexed pages. Each bucket was traced to the site with the URL Inspection API over all 858 sitemap URLs, Search Analytics and `curl` (plan `docs/code-plan/plans/2026-11-07-gsc-coverage-fixes.md`). The rules below remove the causes that sit in this repository.
- **Root `404.html`:** `public/404.html` reaches `output/404.html` through `copyAssets`. Without a top-level `404.html`, Cloudflare Pages runs in single-page-app mode and answers every unknown URL with the home page and status 200, which Google reported as soft 404s and duplicates. Never delete it. Under `/books/<slug>/` the book's own mdBook `404.html` is the nearest one and still applies.
- **Moved chapter URLs:** when a chapter file is renamed or removed and its old URL had search impressions, add a 301 line to `public/_redirects` (`<old extensionless path> <new extensionless path> 301`). Cloudflare allows 2,000 static rules. Signed-out visitors to a gated old path still get the middleware's 401 first; verified search bots pass through and get the 301.
- **Hub pages:** every indexable hub page (`/`, `/about`, `/contribute`, `/donate`, `/appreciation`, `/statistics`, `/dmca`) carries one absolute self canonical and its own meta description; `sign-in`, `sign-up` and `offline` carry `noindex`. Hub links use the extensionless URL (`/about`, never `/about.html`): Pages answers every `.html` URL with a 308.
- **Chapter 1 and the book root:** mdBook writes the first chapter's content into the book root, so the two pages are duplicates. The first chapter's `rel="canonical"`, `og:url` and `hreflang` point at the book root (`canonicalUrl` in `scripts/inject-gating.ts`), and the sitemap leaves chapter 1 out (`check-seo.ts` fails the build when it is listed). Book pages carry `hreflang="id"` and `hreflang="x-default"` to the same canonical and never `hreflang="en"` (check-seo R2, `hreflangError`); hub pages and `offline.html` declare `<html lang="id">` in their HTML, and the hub's i18n runtime (`apps/hub/src/scripts/i18n-runtime.js`) then sets `lang` to the visitor's locale (the `dawnbook_lang` cookie, default `en`) while it swaps the `data-i18n` texts. Its meta description stays its own opener (section 8).
- **Chapter 1 stays public in the client gate:** chapters 2 and later get the `free_chapter_viewed` setter from inject-gating, chapter 1 does not. Before 2026-11-07 a signed-out reader (and Google's renderer) landing on chapter 1 was sent to `/sign-in` by `books/shared-script.js`, and Google recorded 28 first chapters as redirects to `/sign-in`. Chapter 1 now carries `<meta name="dawnbook-free-chapter" content="1">`, and `isPublic` in `shared-script.js` treats a page with that meta as public.
- **Sitemap `lastmod`:** `scripts/generate-sitemap.ts` takes each page's date from the last git commit that touched its source (`gitLastmods`: the chapter `.md` for a chapter, the book folder for its root, all books for `/`). A page without git history, such as a premium chapter whose source lives in the private repo, gets no `lastmod`. `changefreq` and `priority` are not written (Google ignores them). Build from a checkout with full history: in a shallow clone `gitLastmods` returns nothing and warns (one grafted commit would give every page the same date), so the sitemap carries no `lastmod` and `check-seo.ts` (R3) fails the build.
- **Sidebar links:** mdBook 0.5 renders the sidebar from `toc-<hash>.js`, whose links end in `.html`. `normalizeTocLinks` (`scripts/builder/normalize-toc-links.ts`, run by `scripts/build.ts` after inject-gating) rewrites them to the extensionless form with the same rule as `normalizeInternalLinks`, and the build fails when it finds no `toc-*.js`. Stored progress paths keep `.html` (section 5); `normalizePath` in `shared-script.js` adds `.html` to an extensionless `/content/` path before comparing.
- **Check:** `bun run build` runs `checkIndexingOutput` after `check-seo.ts` and exits 1 on any problem; alone, `bun run scripts/check-indexing-output.ts [outputDir]` exits 1 and names each problem in a finished build (missing `404.html` or `_redirects`, hub canonicals and noindex, `.html` hub or sidebar links, chapter 1 canonical, meta and sitemap entry, a sitemap with one `lastmod` for every page).
- **After a deploy that changes these rules:** resubmit the sitemap with the owner's write-scope OAuth token (`GSC_OAUTH_REFRESH_TOKEN_TULIS` in `~/cloudflare/.env`), and the owner starts "Validate fix" in Search Console for the affected reasons.
- **Revert:** delete `public/404.html` and `public/_redirects`; revert the pull request of plan `2026-11-07-gsc-coverage-fixes` for the code changes and this section.

## Cloudflare — WAJIB pakai `cf`, bukan `wrangler` (ditambahkan 2026-09-29)

`cf` (Cloudflare CLI v1.0.0-beta.5) terpasang global di `~/.local/bin/cf` dan
mencakup 3.000+ operasi API. Untuk **semua** operasi Cloudflare, pakai `cf`.
Jangan pakai `wrangler` / `npx wrangler` / `bunx wrangler`, kecuali pada tiga
kondisi di bawah.

**Auth sudah otomatis.** `~/cloudflare/.env` memuat `CLOUDFLARE_API_TOKEN` dan
`CLOUDFLARE_ACCOUNT_ID`, yang di-load `~/.bashrc` untuk shell interaktif.
Tidak perlu `cf auth login`. Kalau `cf` bilang tidak terautentikasi, cek
`cf auth whoami`. Jangan pernah mencetak nilai token.

### Tetap pakai `wrangler` — hanya tiga kondisi

Alasannya sudah diukur, bukan dugaan:

1. **CI / GitHub Actions.** Runner tidak punya `cf` terpasang, dan pipeline
   Snipset memakai Bun. Perintah `wrangler deploy` di `.github/workflows`
   dibiarkan apa adanya.
2. **`wrangler pages dev`.** Tidak ada padanan di `cf`. `cf pages` hanya punya
   `deploy` dan `projects`; `cf pages dev` keluar dengan exit 1.
3. **Worker esbuild / Rust / Python.** `cf` sendiri mendelegasikan ke wrangler
   untuk kasus ini secara sengaja (pengumuman Cloudflare 2026-09-28).

### Cari command, jangan menebak nama

`cf` punya 3.000+ perintah. Wajib mencari, bukan menebak:

```bash
cf cli search "list d1 databases"    # JSON berisi command yang cocok
```

### Empat jebakan yang sudah diukur

1. **Grup resource memakai bentuk jamak**: `buckets`, `namespaces`,
   `projects`, `accounts`, `zones`. Bentuk tunggal tidak ada.
   Salah: `cf r2 bucket list` (exit 1). Benar: `cf r2 buckets list` (exit 0).
2. **Grup tanpa subcommand hanya mencetak help, dan exit 0.**
   `cf zones` keluar 0 tanpa satu pun request API. Yang benar: `cf zones list`.
3. **Exit 0 tidak selalu berarti berhasil.** `cf init` tanpa argumen mencetak
   kotak `Error` tetapi tetap exit 0. Periksa isi output, bukan hanya `$?`.
4. **`cf dev` menolak argumen.** `cf dev --port 8799` ditolak; `cf` mendeteksi
   `vite` dan menyuruh menjalankan `npx vite` langsung untuk opsi Vite.

### Output bawaan adalah JSON

Jangan memakai `--json` seperti pada wrangler; `cf` sudah JSON secara default.
Saring dengan `jq` (terpasang, jq 1.8.2):

```bash
cf d1 list    | jq -r '.[].name'
cf zones list | jq -r '.[].name'
cf kv namespaces list | jq -r '.[].title // .[].id'
```

backup `<file>.bak-cf-20260929`.

## Tool Pencarian Kode: ripgrep, tgrep, grep (Audit 2026-09-30)

Gunakan **ripgrep (`rg`)** sebagai alat pencarian utama di seluruh repo ini:
- Path: `/usr/bin/rg` via symlink `~/.local/bin/rg` dengan global `--smart-case` dan `--max-columns=200` (`~/.config/ripgrep/config`).
- Hindari `tgrep` untuk pola < 3 karakter atau jika repo belum di-index (`tgrep` jatuh ke linear scan 150x lebih lambat).
- DILARANG menjalankan `tgrep` pada `/tmp` (memicu kernel SIGBUS crash).
- `grep` otomatis mengalihkan query direktori ke `tgrep` bila aman dan mendelegasikan ke GNU grep untuk stdin, single file, dan path volatile (`/tmp`, `/proc`).
