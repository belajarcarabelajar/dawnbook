## From section 28 (Telegram Announcement of New Books (Added 2026-10-21))

- **Bot rights:** in the group only admins may post (the default member permission `can_send_messages` is `false`, read with `getChat` on 2026-10-21), so the bot must stay an admin of the group; it needs no other admin right.
- **Bot webhook:** the bot used to feed an n8n workflow through a webhook. The workflow was long inactive, and the owner had the webhook removed on 2026-10-21 so `getUpdates` could read the group's chat id (previous state and revert: `~/.local/share/telegram-bot-backups/20261021-wansagent002-webhook/`). While any webhook is set, `getUpdates` returns 409; `sendMessage` works either way. To find a chat id, send `/start@wansagent002_bot` in the group (privacy mode passes commands) and read `getUpdates`.
- **Old-book broadcast (added 2026-10-30):** the books that were live before this announcement started were never posted, so `scripts/broadcast-old-books.ts` posts them to the same group through the same bot, one a day, in exactly the new-book format above, and stops with a desktop notification once all are sent. Spec, plan and issue: `docs/code-plan/specs/2026-10-30-dawnbook-old-book-broadcast-design.md`, `docs/code-plan/plans/2026-10-30-dawnbook-old-book-broadcast.md`, #215.
- **Where and when it runs:** a systemd user timer on the owner's laptop starts it at 19.00 WIB, with catch-up runs at 20.00 and 21.00; the unit templates live in `scripts/systemd/`. The laptop is an owner decision of 2026-10-30: bots cannot schedule Telegram messages, the Cloudflare cron slots are full, and Actions are off (section 19). The timer is persistent, so it makes up a trigger missed during sleep, and the script's own Asia/Jakarta window is what stops a late post.
- **Frozen queue:** `init` builds the queue once from the live `manifest.json`: every book whose Hub date is before 2026-10-21 00.00 WIB, oldest first, ties broken by slug. It must run from the repo root on `main`, writes `~/.local/state/dawnbook-broadcast/state.json` (file mode 600, folder 700), and refuses when a state already exists; a title changed after `init` is not picked up.
- **Its brakes:** in this order, `run` exits when another run holds its lock (a kernel `flock` on `run.lock`, released when that process exits, so a crash never leaves a stale lock); without a state it notifies and exits 1 (it never initialises); a pause makes it exit; a leftover in-flight send pauses it and notifies; it sends nothing outside 19.00 to 21.59 Asia/Jakarta and at most one book per WIB date; an empty queue notifies once that all are sent and stops; without `TELEGRAM_BOT_TOKEN` or `DAWNBOOK_TELEGRAM_CHAT_ID` in `~/cloudflare/.env` (the only two keys it reads) it logs and exits 0. The first chapter's link must answer HTTP 200 with no redirect followed, or the run notifies and exits 1 without using up the day. The send is tried once and never retried, and any send error pauses the job with the token redacted and notifies.
- **Commands** (from the repo root, `bun run scripts/broadcast-old-books.ts <command>`): `init --dry-run` prints every message and writes nothing, `init` writes the state, `run [--dry-run]` is what the timer calls, `status` prints the sent count, the next title and any pause reason (exit 1 when not initialised), and `pause [--reason <text>]` stops the job. `resume` clears a pause that had no send attempt. After a pause from a send attempt, check the group first: `resume --sent` records the book as sent, `resume --not-sent` keeps it next.
- **Exit codes, notifications and logs:** 0 means nothing is needed, 1 means attention is needed and shows in `systemctl --user --failed`, 2 is a usage error. Notifications are `notify-send` desktop messages in Indonesian; the log is `journalctl --user -u dawnbook-broadcast`.
- **Install, kill switch and revert:** enabling the timer is a separate owner decision, taken after `init`: `cp ~/Proyek/dawnbook/scripts/systemd/dawnbook-broadcast.service ~/Proyek/dawnbook/scripts/systemd/dawnbook-broadcast.timer ~/.config/systemd/user/ && systemctl --user daemon-reload && systemctl --user enable --now dawnbook-broadcast.timer`. Kill switch: `systemctl --user disable --now dawnbook-broadcast.timer`; `pause` also stops it, and so does removing either Telegram key, though that silences local new-book announcements too. Revert of the broadcast alone: the kill switch, then `rm ~/.config/systemd/user/dawnbook-broadcast.service ~/.config/systemd/user/dawnbook-broadcast.timer && systemctl --user daemon-reload`, delete `~/.local/state/dawnbook-broadcast/`, and revert its pull request.
